# Персональная скидка в ценах каталога

## Проблема

SHM (`Core::Service::price_list`, роут `GET /shm/v1/service/order`) уже считает
персональную скидку пользователя (`users.discount`) и отдаёт в каждой позиции
прайса поля `discount`, `cost_discount`, `real_cost`. ЛК их выбрасывает в
`normalizeCatalogService` и рисует голый `cost` — пользователь со скидкой 50%
видит полную цену, а списывается половина.

Скидка у 103 из 1255 пользователей — баг видит заметная часть базы.

## План

- [x] Добавить в тип `Service` поля `discount` / `real_cost`
- [x] Пробросить их в `normalizeCatalogService` (фолбэк на `cost`, если SHM старый)
- [x] Утилита `utils/price.ts`: `servicePrice()` + `formatPrice()`
- [x] `ServicesPage`: цена со скидкой в карточке каталога и в модалке смены тарифа
- [x] Сортировка каталога — по цене со скидкой
- [x] В корзину (`saveCart`) писать цену со скидкой
- [x] Тесты на нормализацию и расчёт
- [x] `tsc` + `vitest`

## Ревью

Правки только на фронте: SHM уже присылал всё нужное, ЛК это игнорировал.
Клиент ничего не пересчитывает сам — берёт `real_cost` из ответа SHM, поэтому
`no_discount` у услуги и любые будущие правила скидок в биллинге учитываются
автоматически. Фолбэк `real_cost ?? cost` оставляет старое поведение, если
поле не пришло.

Осознанно не тронуто:
- `PaymentsPage` — уже показывает номинал и сумму к списанию по forecast;
- `ActiveSubscription.tsx` — мёртвый компонент, нигде не смонтирован;
- бонусы (`real_cost_with_bonuses`, `cost_bonus`) — отдельная задача, к скидке
  отношения не имеют.
