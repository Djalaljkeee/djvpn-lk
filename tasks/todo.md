# База знаний из переписки поддержки

## Задача

Экспорт рабочего аккаунта поддержки `@help_djvpn` (Telegram, 248 диалогов,
6 284 сообщения, ноябрь 2023 — сентябрь 2026) — единственное место, где лежат
реальные вопросы пользователей и рабочие ответы операторов. Нужно вытащить из
него частотный список вопросов и канонические ответы, чтобы заполнить базу
знаний (виджет поддержки в ЛК, бот, `setup.html`).

## План

- [x] Распаковать архив (RAR7 — `7z` не берёт, нужен `unrar 7.x`), достать
      `result.json` без медиа
- [x] Разделить реплики на клиентские и операторские по `from_id`
- [x] Частотный анализ тем по клиентским сообщениям (уникальные диалоги, не
      сообщения — иначе один болтливый чат перекашивает статистику)
- [x] Вытащить пары «вопрос → ответ оператора» (599 пар) и прочитать их целиком
- [x] Собрать повторяющиеся шаблоны ответов оператора
- [x] Сверить факты с кодом (`backend/vpn_setup.py`, `frontend/src/api/user.ts`,
      `frontend/src/utils/price.ts`, `setup.html`), а не с памятью
- [x] Написать `docs/knowledge-base/faq.md`

## Ревью

- Частота считается по **числу диалогов**, где тема всплыла, а не по числу
  сообщений: в переписке есть чаты на 220 сообщений, они бы утопили статистику.
- Ответы писались не «как правильно», а как их реально даёт поддержка —
  формулировки взяты из повторяющихся шаблонов оператора. Там, где оператор
  отвечал по-разному, выбран вариант, который в переписке закрывал вопрос.
- Цены намеренно не зафиксированы как факт: источник истины — прайс SHM
  (`servicePrice`), в переписке они менялись. Указан только порядок величин
  с датировкой.
- Комиссия рефералки: в переписке 15%, в коде `DEFAULT_COMMISSION = 15` —
  fallback, реальный процент приходит из SHM (комментарий в `api/user.ts`
  говорит о 20%). В FAQ — формулировка без числа, с отсылкой к ЛК.
- Раздел «Что чинить в продукте» оставлен: половина обращений — это не
  вопросы, а последствия трёх багов (дубли услуг, конфиг не обновляется
  автоматически, платёжная страница). База знаний их не лечит.
- Отдельный JSON под импорт не делал: пока нет кода, который его читает,
  это второй источник правды, который разъедется с markdown.

# База знаний в личном кабинете

## Задача

FAQ из переписки лежал в `docs/` — то есть нигде для пользователя. Нужен
раздел в самом кабинете: с поиском, категориями и ссылкой из виджета
поддержки, чтобы человек находил ответ до того, как напишет в очередь.

## План

- [x] `frontend/src/data/faq.ts` — 71 вопрос из `docs/knowledge-base/faq.md`,
      типизированные ответы (абзацы, нумерованные шаги, ссылки, теги)
- [x] Поиск: токены + синонимы + грубая основа слова вместо подстроки
- [x] `frontend/src/pages/FaqPage.tsx` — поиск, категории со счётчиками,
      аккордеон на `<button>`, deeplink `/faq#id`
- [x] Маршрут `/faq`, значок в шапке (`sm:`) и пункт в меню профиля (мобила)
- [x] Ссылка на базу знаний в пустом состоянии виджета поддержки
- [x] Переводы UI в `ru.json` / `en.json`
- [x] Тесты: целостность данных, поведение поиска, замер на 27 реальных
      запросах, рендер страницы (16 новых, всего 87)
- [x] Проверка в браузере: десктоп, 360px, deeplink, пустая выдача, виджет

## Ревью

- Аккордеон на `<button>`, а не на `<details>`/`<summary>`: по уроку из
  `lessons.md` `display: flex` на `<summary>` ломает нативный toggle в
  Safari < 17, а без flex не поставить иконку справа.
- Контент только на русском — решено заказчиком. Задел под перевод (поле `en`
  в типе) убран: переводить не планируется, а неиспользуемое поле в типе живёт
  ровно до тех пор, пока кто-то не начнёт его заполнять наполовину. Английский
  UI показывает те же русские ответы и предупреждает плашкой `faq.ruOnly`;
  сами подписи интерфейса (заголовок, поиск, категории) переведены — иначе в
  EN-режиме страница показывала бы сырые ключи.
- Отдельного JSON под импорт по-прежнему нет: `faq.ts` и есть источник, ЛК
  читает его напрямую. Второй формат разъехался бы с первым.
- Ответы намеренно не дублируют `setup.html`: там пошаговая установка со
  скриншотами, здесь — короткий ответ и ссылка в инструкцию.
- Данные и разбор переписки держать согласованными: `docs/knowledge-base/faq.md`
  — источник с частотами, `faq.ts` — то, что видит пользователь.
