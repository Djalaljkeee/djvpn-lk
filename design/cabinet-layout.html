Карта навигации и маршруты

02 · структура

Приложение — одностраничное. Всё, что внутри PrivateRoute → Layout, делит общий хедер, фон с частицами и мобильный таббар. Вход, смена пароля и короткая реферальная ссылка живут вне каркаса.

Дерево маршрутов

/login — вход/регистрация/OTP/сброс
/r/:id — реф-ссылка → захват → «/»
/change-password — приват, вне Layout
/ — PrivateRoute → Layout
  ├─ index Главная (DashboardPage)
  ├─ /services Подписки
  ├─ /payments Платежи
  ├─ /profile Профиль
  └─ /referrals Рефералы (нет в таббаре)
* → redirect на «/» или /login?token=
/setup.html — статическая страница инструкций

Точки входа

  • Telegram Mini App — TelegramWebAppGate ловит initData, логинит молча, показывает экран-заглушку «Авторизация…» со спиннером.
  • Браузер — Telegram Login Widget либо логин/пароль на /login.
  • Письмо со сбросом пароля — любой URL с ?token= ведёт на форму нового пароля.
  • Реферальная ссылка — /r/ref-42 или ?ref=42, id живёт в localStorage до регистрации.

Основные пользовательские пути

Первая покупка: Главная (нет подписки) → «Оформить подписку» → каталог → «Подключить тариф» → не хватает средств → модалка → Платежи → оплата → баннер корзины.

Подключение устройства: Главная → «Подключиться» → модалка «Настройка VPN» (шаг 1 — установка приложения, шаг 2 — импорт подписки/QR).

Продление: Платежи → «Предстоящие расходы» → пополнение, либо карточка «Продление N-го» на Главной.

Реферальный доход: Профиль → Реферальная программа → копирование ссылки/QR → таблица рефералов и уровень.
«Рефералы» — полноценный раздел, но попасть в него можно только через список в профиле: в таббаре и хедере пункта нет.

Логика экрана

  • Внутри Telegram Mini App виджет и разделитель «или» скрываются — остаётся только логин/пароль.
  • Если виджет Telegram не загрузился (провайдер блокирует), показывается текстовая подсказка вместо него.
  • Регистрация добавляет поля «Имя», Email, «Повторите пароль», капчу и два обязательных чекбокса (152-ФЗ и оферта).
  • После регистрации — режим verify-email с 6-значным OTP (OtpVerify, 566 строк, автофокус и вставка из буфера).
  • Ссылка из письма с ?token= открывает режим «Новый пароль» с любого пути.
  • Реферальный ?ref= захватывается до маршрутизации и переживает OAuth-редирект.

Компоненты

  • BrandLogo — картинка 48–72 px + вордмарк.
  • Field — лейбл + «(необязательно)» + слот, иконка слева внутри поля.
  • ForgotPasswordBlock, ResetPasswordBlock — режимы внутри той же карточки.
  • Ошибка — розовая плашка под формой, успех — зелёная.

Данные

  • Всё из одного /api/dashboard: services, remna_info (трафик и лимиты), devices, orders, forecast.

  • Лимит устройств: hwid_device_limit, иначе limit_ip, иначе 5.
  • Пробный тариф зашит константой TRIAL_SERVICE_ID = 4.

Секции сверху вниз

  • Баланс — крупная сумма, ниже бонусный баланс, если он больше нуля.
  • Неоплаченные услуги — янтарный блок: сумма к оплате, список позиций, «не хватает N ₽» с кнопкой «Пополнить» (скроллит к блоку пополнения) либо зелёная плашка «Баланса достаточно».
  • Предстоящие расходы — прогноз биллинга: дата, позиции, итог к списанию. За 3 дня и меньше вся секция становится янтарной, заголовок — «Списание завтра» / «Оплата просрочена».
  • Промокод — поле + синяя кнопка «Активировать», результат зелёной или розовой плашкой.
  • Пополнение — сумма, 4 быстрых номинала (199 / 499 / 899 / 1599 ₽), список платёжных систем с лимитами; сохранённая карта имеет кнопку отвязки.
  • История операций — сворачиваемая, по 25 записей на страницу, приход зелёный со стрелкой ↙, расход розовый ↗; нулевые операции скрываются.

Защита от двойной оплаты

  • usePaymentGuard: пока платёжная вкладка открыта — предупреждение и блокировка остальных платёжных систем; активная остаётся кликабельной, чтобы вернуть фокус той же вкладке.
На странице три денежных блока подряд (баланс, неоплаченные, прогноз) — они визуально почти одинаковые и различаются только цветом рамки.

Как работает мастер

  • Контент шага (title, app_name, ссылки, deeplink, QR) приходит с бэкенда по подписке или id услуги — фронт не знает про конкретные приложения.
  • Платформа определяется автоматически, показывается пилюлей над шагом.
  • Для iOS предусмотрены две региональные ссылки (основная и альтернативная).
  • Шаг 2 всегда даёт три пути: кнопка-deeplink, QR-код и копирование ссылки.
  • Если ссылку получить не удалось — вместо шагов показывается текстовая инструкция.
  • Модалка — z-50, скролл внутри (max-h-80vh), закрытие по скриму.
Мастер и «Инструкции» (/setup.html) — два независимых источника одной и той же справки: первый динамический в модалке, второй статический вне SPA.

  • Строка списка «иконка + текст + значение справа» — устройства, платежи, рефералы, тарифы.
  • Пагинация «25/стр · 1–25 / 42 · ‹ ›» — продублирована в платежах и рефералах.
  • Плашка результата зелёная / розовая / янтарная — промокод, ошибки, статусы.
  • Прогресс трёх видов: линейный бар, кольцо SVG, сегменты и точки.

Что бросается в глаза

  • Два визуальных языка. Главная, Подписки, Платежи и Рефералы — «стекло» с радиусом 28–32 px. Профиль и мастер подключения — плоские карточки на surface-1/2/3 с радиусом 12–16 px.
  • Дублирование данных. Остаток дней — в 3 местах, устройства — в 3, баланс — в 3, трафик — в 2. Одна и та же сущность выглядит каждый раз по-новому.
  • Главная почти ничего не решает. Полезных действия два — «Подключиться» и «Обновить прогноз»; всё остальное — переходы на другие экраны.
  • Подписки перегружены. Восемь блоков подряд + скрытый каталог + список устройств на одном маршруте.
  • Рефералы спрятаны в списке профиля, хотя это самый проработанный экран.
  • Нет заголовков страниц нигде, кроме «Баланс» и «Реферальная программа», — непонятно, где ты находишься.
  • Пять модалок сверстаны независимо, но по одному шаблону: скрим + sheet + две кнопки.
  • Локализация наполовину. i18n подключён (ru/en), но большинство строк вшито в JSX по-русски — при редизайне это отдельная задача.
  • Мобильный приоритет. Десктоп получает те же карточки в один столбец шириной 1152 px — воздух не используется, сеток на 2–3 колонки почти нет.

Наследуемые ограничения

  • Данные приходят одним запросом /api/dashboard — экраны привязаны к его структуре.
  • Статусы услуг из SHM: 0/2 — не оплачена, 1 — активна, 3 — удалена.
  • Лимиты устройств и трафика — из Remnawave, могут отсутствовать (тогда «--» и «безлимит»).
  • Тема только тёмная; светлой в коде нет вообще.
  • Кабинет работает и как Mini App внутри Telegram — верхняя область и кнопка «назад» принадлежат клиенту Telegram, дизайн должен это учитывать.
  • Safe-area снизу учтён классом .safe-bottom.
